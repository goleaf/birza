# Quick Task 260607-s2k: Refactor Order Status Workflow

## Problem

Order lifecycle is split between `orders.status`, `orders.payment_status`, `Order::STATUS`, `App\Enums\OrderStatus`, helper arrays, and Blade `match` blocks. Seller and buyer status changes write directly to the order, do not create history, and only partially enforce transition and ownership rules.

- files:

  - `app/Policies/OrderPolicy.php`

- verify: Unit/feature tests cover valid and invalid transitions, ownership, history, notification, and rollback.
- done: No status-changing surface writes `orders.status` directly.
